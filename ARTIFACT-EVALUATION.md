# Artifact Evaluation Guide — BotLens

**Paper:** Kofi Ampomah and Tu Le. *Measuring Users' Security and Privacy Concerns
About Third-Party Community Bots on Discord.* NDSS Symposium 2027.
https://dx.doi.org/10.14722/ndss.2027.230535

This document maps each claim in the paper to the command that reproduces it, the
expected output, and the approximate time and hardware required. Run every command
from the repository root (the directory that contains this file).

## 2. Setup and minimal working example (≈10 minutes, CPU only)

Get the artifact from https://github.com/ua-spectral/BotLens (or its DOI-backed
Zenodo archive, which holds the same files), then:

```bash
git clone https://github.com/ua-spectral/BotLens.git && cd BotLens   # or unpack the Zenodo archive
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements-lock.txt                  # exact versions used for the paper
python -m zipfile -e botlens-ndss-data.zip .          # unpacks the data into data/
```

`requirements-lock.txt` pins the direct dependencies as installed on the machine that
produced the paper's results (Python 3.11.9), including `pytest`. Nothing in §3–§4
needs a GPU or PyTorch; `torch` is required only for re-running Stages 3, 4 and 6
(see the note in `requirements-lock.txt`).

The data ships as `botlens-ndss-data.zip` because one of its files unpacks to
515 MB, beyond GitHub's per-file limit; after the last command above, `data/` sits
beside `config/`. Verify it:

```bash
cd data && sha256sum -c SHA256SUMS.txt && cd ..      # macOS: shasum -a 256 -c SHA256SUMS.txt
```

All 46 files should report `OK`. Then run the smoke tests:

```bash
python -m pytest tests/test_smoke.py -v
```

This is the minimal working example: it needs no data, no GPU and no network, and
finishes in seconds. All 17 tests should pass. `test_taxonomy_matches_paper` asserts
the taxonomy holds exactly 31 themes grouped 7 / 7 / 8 / 9, matching Table V; the
others check that the scripts, figure names and MCP tools match the paper.

## 3. Reproducing the paper's results (E1–E4)

Everything in this section runs on a CPU from the shipped data. No GPU, no Ollama and
no network access is required. Figures are written to `figures/` and tables to
`data/results/`. Each command was run against this archive before release; §9 records
the observed output.

### 3.1 E1 — Headline numbers (Table I, Sec. IV-A)

```bash
python scripts/stage7_analysis.py
```

Writes `data/results/analysis_summary.json`:

```json
{
  "total_reviews": 183142,
  "privacy_reviews": 8832,
  "sprr_overall": 4.82,
  "num_themes": 14,
  "top_theme": "Data Sharing",
  "top_theme_tpr": 30.5
}
```

Supports: 183,142 reviews; 8,832 S&P-relevant; observed pipeline yield 4.82%
(abstract, Table I, Sec. IV-A); Data Sharing as the top theme at 30.5% TPR. It also
rewrites `theme_distribution.csv`, `sprr_by_bot.csv`, `sprr_by_category.csv` and
`emotion_by_theme.csv`, each byte-identical to the shipped copy. `num_themes` counts
the themes with at least 50 reviews (see `data/README.md`). Runtime < 1 min.

Two Table I / Sec. IV-D claims come from the bot metadata rather than the reviews,
because only 11,980 of the 23,102 bots received any review:

```bash
python -c "
import pandas as pd
m = pd.read_csv('data/processed/bot_metadata_cleaned.csv', low_memory=False)
blob = m['short_description'].fillna('') + ' ' + m['long_description'].fillna('')
pp = blob.str.contains('privacy policy', case=False, na=False)
print('unique bots:', m['bot_id'].nunique())
print('reference a privacy policy:', pp.sum(), f'({100*pp.sum()/len(m):.2f}%)')
"
```

Expected: `unique bots: 23102` and `reference a privacy policy: 177 (0.77%)`.

## 4. E5 — The BotLens MCP server (Sec. V)

The server reads three files from `data/processed/`:
`all_reviews_classified.csv`, `privacy_reviews_full.csv` and
`bot_metadata_cleaned.csv`. Loading them takes about 10 s at startup; after that
every tool call is a lookup. The environment variable `BOTLENS_DATA_DIR` must point
at the repository root (the directory that contains `data/`).

The six tools from Sec. V-B2 are `get_bot_signals`, `get_taxonomy_breakdown`,
`get_review_samples`, `compare_bots`, `list_high_salience_bots` and
`scan_server_bots`. They follow Algorithm 1 (Appendix A): theme counts come from the
31-theme labels (TaxonomyFlags, each review counted under its primary theme), and a
bot that has no reviews falls back to a permission audit from its Top.gg metadata
(PermissionAudit).

### 4.1 Quickest check: the example client (no MCP application needed)

```bash
python mcp_server/example_client.py
```

This uses the official MCP Python SDK (installed with `mcp`) to start the server over
stdio — exactly as an MCP application would — lists the tools, and runs both use
cases. Expected: `Server exposes 6 tools`, then the two reports below. To call any
single tool:

```bash
python mcp_server/example_client.py --tool get_taxonomy_breakdown --arg bot_name=Wick
python mcp_server/example_client.py --tool compare_bots --arg "bot_names=Wick, Carl-bot, Dyno"
```

### 4.2 Use Case 1 (Fig. 15): checking one bot

`get_bot_signals` with `Wick`. Expected: SPRR 28.92% (72 of 249 reviews), average
rating 4.3/5, ~823,608 servers, `['ADMINISTRATOR']`, top themes Data Security (n=35),
Data Sharing (n=21), Data Exposure (n=5), and sentiment 52.8% positive (n=38) / 40.3%
negative (n=29) / 6.9% neutral (n=5).

### 4.3 Use Case 2 (Fig. 16): auditing a server

`scan_server_bots` takes the **absolute** path of a text file with one bot name per
line. The example client writes this file for you; to do it by hand, create
`bots.txt` containing:

```
Wick
Auttaja
Carl-bot
Dyno
Dank Memer
Mudae
```

These are the six bots in Fig. 16. Fig. 16 prints the fifth as `Dank Member`; the
bot is named `Dank Memer` on Top.gg and in the dataset, and the values in that row
are Dank Memer's. Use the spelling above.

Expected: all six bots found; three above 10% SPRR — Wick 28.9% (72/249), Auttaja
23.5% (16/68), Carl-bot 16.6% (94/565) — then Dyno 8.6% (31/361), Dank Memer 3.3%
(106/3190) and Mudae 0.0% (0/9). Permission counts 1, 20, 23, 0, 11, 6; the six S&P
counts total the 319 reviews in Fig. 16's header; top themes (first listed) Data
Security, Data Exposure, Data Sharing, Data Collection, Data Sharing, — as in
Fig. 16's "Top theme" column. The report closes with
`3 bot(s) show high S&P discussion salience`.

**Metadata fallback (Algorithm 1, line 23).** Add `MEE6` to the file: MEE6 is listed
on Top.gg (19.5M servers) but has no reviews in the dataset, so it appears under
"No reviews in the dataset — permission audit from Top.gg metadata" with 26
permissions, including ADMINISTRATOR, instead of being reported as not found.
10,637 of the 23,102 bots are in this situation.

### 4.4 Using Claude Desktop (optional)

Claude Desktop is available for macOS and Windows.

1. Open Claude Desktop → **Settings** → **Developer** → **Edit Config**. This opens
   `claude_desktop_config.json`, located at
   - macOS: `~/Library/Application Support/Claude/claude_desktop_config.json`
   - Windows: `%APPDATA%\Claude\claude_desktop_config.json`
2. Add the server. Use **absolute paths**, and the Python interpreter of the
   environment you installed into in §2 (e.g. `/path/to/.venv/bin/python`, or
   `C:\\path\\to\\.venv\\Scripts\\python.exe` on Windows — JSON needs doubled
   backslashes):

   ```json
   {
     "mcpServers": {
       "botlens": {
         "command": "/absolute/path/to/.venv/bin/python",
         "args": ["/absolute/path/to/botlens-ndss/mcp_server/server.py"],
         "env": { "BOTLENS_DATA_DIR": "/absolute/path/to/botlens-ndss" }
       }
     }
   }
   ```

3. Quit Claude Desktop completely (menu bar / system tray → Quit, not just closing
   the window) and start it again. The tools menu in the message box should list
   `botlens` with six tools.
4. Ask, for example, *"What S&P signals are reported for Wick?"* (Use Case 1) or
   *"Scan the bots listed in /absolute/path/to/bots.txt"* (Use Case 2).

If the tools do not appear, open **Settings → Developer**: it shows the server's
status and a link to its log. The usual causes are a relative path, or a `command`
pointing at a Python without the packages from §2.

Any other MCP client works the same way: run `python mcp_server/server.py` with
`BOTLENS_DATA_DIR` set. **The server is not interactive** — it speaks JSON-RPC over
stdin/stdout, so started in a bare terminal it waits silently for a client. Press
Ctrl+C to exit.

### 4.5 Latency (Sec. V-D)

```bash
python mcp_server/benchmark_latency.py
```

Replays a session with the paper's composition (11 × `get_bot_signals`, 1 ×
`get_taxonomy_breakdown`, 4 × `get_review_samples`, 6 × `scan_server_bots`) and
prints mean / min / max per tool in milliseconds, from the server's own timer. The
paper reports 1.7 / 1.6 / 1.9 ms for the three lookup tools and 14.7 ms mean for
`scan_server_bots`. Absolute numbers depend on the CPU; the claim under test is that
calls stay in the low-millisecond range because every classification is precomputed.
On our verification machine every tool averaged under 1 ms (§9). Startup loading
(~10 s) is one-time cost and is not included, as in the paper.

## 5. Out of scope — please do not run

`scrapers/discord_server_scanner.py` automates a login to a real Discord user
account. That is contrary to Discord's Terms of Service and requires real credentials
in `.env`. It is included only so the record of how the Use Case 2 manifest was
produced is complete. No result in the paper depends on running it — use the
plain-text manifest in §4.3 instead.

`scrapers/topgg_metadata_scraper.py` and `topgg_reviews_scraper.py` access Top.gg
live. They are rate-limited and were run over several weeks in early 2026; Top.gg's
markup has changed since, so they are provided as a record of collection methodology
rather than as a re-runnable step. The crawl output is superseded by the shipped data.

## 6. What cannot be re-run end-to-end, and why

- **Raw crawl (Stage 0 input).** The raw Top.gg crawl is not redistributed: it
  contains reviewer display names that we strip during preprocessing and do not
  publish. The shipped data begins after that removal.
- **Stages 1, 1b, 5** require a local Ollama with `llama3:8b` and ~54 GPU-hours on an
  RTX 5090 for the 30% labeling budget (~200 hours without incremental labeling).
  Outputs are non-deterministic even at temperature 0.1, so exact label-for-label
  reproduction is not expected; we ship the resulting labels instead.
- **Stage 3** fine-tuning requires the GPU described above. A saved model directory
  is ~1.7 GB, and a full training run retains every epoch checkpoint (~52 GB for the
  production run). The fine-tuned model is not included; contact us if you need it.
- **Table III** (active learning) is not reproducible from this artifact; the
  corresponding runs were not preserved.
- **Reported classifier metrics** (F1 = precision = recall = 0.938) come from a
  98-review evaluation split with 16 positives. The paper reports 95% Wilson
  intervals of roughly 0.72–0.99 and treats these as performance under that setup
  rather than generalization estimates (Sec. III-C4).

## 10. Changes since artifact evaluation

This public release incorporates the AE reviewers' feedback. No result or figure value
changed.

- **BotLens matches Sec. V and Algorithm 1.** `get_taxonomy_breakdown` now counts the
  31 taxonomy themes (previously keyword matches against a superseded concept list);
  bots without reviews get the PermissionAudit metadata fallback; tool output no
  longer describes a bot as "safe" or "safest"; per-bot signals are precomputed at
  startup, so every lookup is well under 2 ms (previously ~13–50 ms for
  `get_taxonomy_breakdown` and `get_review_samples`).
- **Names follow the paper.** The two legacy `rq4_*` scripts are merged into
  `rq3_permissions_metadata.py`, which also prints every Sec. IV-D statistic; every
  generated figure is named by its paper figure number.
- **Only the paper's figures are generated**, drawn as they appear in the paper. The
  continent-level figures, which are not in the paper, were removed.
- **Unused code removed:** the uncalled KPSS test and two unreported analyses in
  Stage 7, and the legacy 33-concept list in the MCP server.
- **Setup:** `pytest` is in `requirements-lock.txt`; `compute_kappa.py` reads
  `data/irr/` directly; all figures go to `figures/` and all tables to `data/results/`.
- **E5:** step-by-step Claude Desktop instructions, an example MCP SDK client, and a
  latency script.
